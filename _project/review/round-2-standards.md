## Verified fixed (spot-checked this round)

- **Tests run**: `docker compose exec -T backend sh -c 'PYTHONPATH=/app python -m pytest /app/tests -q'` → **22 passed in 0.36s**. Discrimination proven: a deliberately-wrong /tmp suite (substring-exploit, substring-PoC, gate-bypass, impossible-truncation assertions) failed 4/4, so the green suite is not rigged; assertions flip when behaviour regresses.
- **RSS fail-loud** (rss.py:31-36): raises on bozo-with-no-entries and on 0 entries; partial-bozo with entries logs a warning. Matches the arXiv zero-item failure mode.
- **Worker health** (worker.py:37-79): fetch exception → failures+1, status error, back-off engages; all-envelopes-failed → error + failures+1; partial → warning + success. No unconditional success path remains. Empty fetch (304/no news) legitimately succeeds.
- **LLM validation** (llm.py:108-112, 155-160; ingest.py:170-193): every model response passes `AnalysisOut.model_validate`; JSON/KeyError/ValidationError → logged heuristic fallback. Analysis rows iterate `ANALYSIS_KINDS` only, labels double-filtered to `ALLOWED_LABELS`, confidence pattern-checked defaulting to `low`. **No unvalidated model output can reach the analyses table** (content also capped at 8000 chars; heuristic path writes no analysis rows).
- **except sweep** (all of backend/app): every `except Exception` either logs + counts (worker, github_releases), logs + falls back to an honest heuristic that fabricates nothing (llm, embed), logs + keeps the DB as plane of record (alerts), retries then raises (db.ensure_bucket), or is the S3 head-object-existence pattern (ingest.py:31) whose put errors still propagate. No fail-silent paths found; none introduced. Remaining narrow misses are findings #1 and #8 above.
- **Secrets**: `git ls-files` shows no `.env`, no key/pem files (only `.env.example` with empty values); `git log --all -- .env` → never tracked; API_WRITE_KEY appears in history only as code references, never a value. docker-compose.yml parameterises `POSTGRES_PASSWORD` (`${POSTGRES_PASSWORD:-intel}`) and dropped the minio defaults (S3 uses `any`); the `intel` fallback default is weak but the DB is 127.0.0.1-bound and it is overridable — acceptable for local dev, noted.
